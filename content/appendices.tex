\section{\textit{AI.RTISANSHIP} technical documentation}

\textit{AI.RTISANSHIP} experiment represented an attempt to capture and digitize traditional pottery techniques through computer vision and machine learning. This technical documentation outlines the implementation pipeline, from data collection through real-time prediction deployment.

\vspace{0.5cm}

The code for this project can be found opened under an MIT license on the following GitHub repository: \href{https://github.com/jmuozan/ML_Sequence_Recognition}{github.com/jmuozan/ML\_Sequence\_Recognition}

\subsection{System architecture overview}

The system implemented a machine learning system organized into seven main sections within a Jupyter notebook environment (\texttt{ML\_Sequence\_Recognition.ipynb}), building from data collection to real-time prediction capabilities.

\vspace{0.5cm}

Technology stack:
\begin{enumerate}
\item MediaPipe for holistic landmark detection (pose and hand tracking)
\item OpenCV for computer vision and video processing
\item TensorFlow/Keras for bidirectional LSTM neural network training
\item Pandas and NumPy for data processing and feature extraction
\end{enumerate}

This system captures 225-dimensional feature vectors from pose and hand landmarks, processes sequences through LSTM networks, and provides real-time feedback about movement correctness.

\subsubsection{Feature extraction system}

\begin{verbatim}
def extract_keypoints(results):
    # Extract pose landmarks (33 points x 3 coordinates = 99 features)
    pose = np.array([[res.x, res.y, res.z] for res in 
                     results.pose_landmarks.landmark]).flatten() \
           if results.pose_landmarks else np.zeros(33*3)
    
    # Extract left hand landmarks (21 points x 3 coordinates = 63 features)
    lh = np.array([[res.x, res.y, res.z] for res in 
                   results.left_hand_landmarks.landmark]).flatten() \
         if results.left_hand_landmarks else np.zeros(21*3)
    
    # Extract right hand landmarks (21 points x 3 coordinates = 63 features)
    rh = np.array([[res.x, res.y, res.z] for res in 
                   results.right_hand_landmarks.landmark]).flatten() \
         if results.right_hand_landmarks else np.zeros(21*3)
    
    return np.concatenate([pose, lh, rh])
\end{verbatim}

\subsubsection{LSTM neural network architecture}

The classification system used a three-layer bidirectional LSTM architecture for temporal sequence recognition.

\begin{verbatim}
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import LSTM, Dense, Dropout, Bidirectional
from tensorflow.keras.regularizers import l2
from tensorflow.keras.optimizers import Adam

# Build bidirectional LSTM architecture
model = Sequential([
    # First bidirectional layer with return sequences
    Bidirectional(LSTM(64, return_sequences=True, activation='tanh'), 
                  input_shape=(sequence_length, 225)),
    Dropout(0.2),
    
    # Second bidirectional layer with L2 regularization
    Bidirectional(LSTM(128, return_sequences=True, activation='tanh', 
                       kernel_regularizer=l2(0.01))),
    Dropout(0.2),
    
    # Final bidirectional layer
    Bidirectional(LSTM(64, activation='tanh')),
    
    # Dense classification layers
    Dense(64, activation='relu'),
    Dense(32, activation='relu'),
    Dense(num_classes, activation='softmax')
])

# Compile model with Adam optimizer
optimizer = Adam(learning_rate=0.001)
model.compile(optimizer=optimizer, 
              loss='categorical_crossentropy', 
              metrics=['accuracy'])

def draw_styled_landmarks(image, results, incorrect_movement):

\section{\textit{CR3ATED} Technical documentation}

The \textit{CR3ATED} web application was developed to test alternative interface approaches for preserving creative agency within digital fabrication workflows. This technical documentation outlines the implementation of the 3D revolution modeling webapp with focus on its main capabilities: 3D generation from drawings, image-based surface modification, and displacement mapping.

\vspace{0.5cm}

The complete source code is available as open-sourced under MIT License at \href{https://github.com/jmuozan/CR3ATED}{github.com/jmuozan/CR3ATED}, and can be accessed at \href{https://jmuozan.github.io/CR3ATED/}{jmuozan.github.io/CR3ATED}.

\subsection{System architecture overview}

This web application implements a complete 3D modeling pipeline using web technologies, dividing functionalities across specific JavaScript modules.

\vspace{0.5cm}

Core technology stack:
\begin{enumerate}
\item Three.js for 3D rendering and scene management
\item WebGL-accelerated graphics through Three.js WebGLRenderer

\subsubsection{STL import functionality}

The application also provides STL file loading capabilities to allow user bring and modify their own models.

\begin{verbatim}
export function handleSTLUpload(params) {
    const file = params.event.target.files[0];
    if (file) {
        const reader = new FileReader();
        
        reader.onload = function (e) {
            const loader = new THREE.STLLoader();
            const geometry = loader.parse(e.target.result);

            if (params.mesh) {
                params.scene.remove(params.mesh);
                params.scene.remove(params.wireframe);
            }

            geometry.computeVertexNormals();
            
            // Store original positions for displacement operations
            geometry.originalPositions = geometry.attributes.position.array.slice();

            const newMesh = new THREE.Mesh(geometry, params.solidMaterial);
            const newWireframe = new THREE.Mesh(geometry.clone(), params.wireframeMaterial);
            newWireframe.visible = false;

            // Default vertical orientation
            newMesh.rotation.x = -Math.PI / 2;
            newWireframe.rotation.x = -Math.PI / 2;

            params.scene.add(newMesh);
            params.scene.add(newWireframe);
        };
        reader.readAsArrayBuffer(file);
    }
}
\end{verbatim}

The import process uses Three.js STLLoader to parse binary or ASCII STL files. The system will automatically compute vertex normals for proper lighting and store vertex positions for posterior displacement operations.

\subsection{Image-based displacement mapping}

\subsubsection{UV coordinate generation}

UV coordinate genration is the responsable of creating the mapping between 2D texture space and 3D mesh surfaces for posterior displacement operations

\begin{verbatim}
export function generateUVs(geometry, displacementSettings) {
    const position = geometry.attributes.position;
    const box = new THREE.Box3().setFromBufferAttribute(position);
    const size = new THREE.Vector3();
    box.getSize(size);

    const uv = new THREE.BufferAttribute(new Float32Array(position.count * 2), 2);
    const positionArray = position.array;

    for (let i = 0; i < position.count; i++) {
        const x = positionArray[i * 3];
        const y = positionArray[i * 3 + 1];
        const z = positionArray[i * 3 + 2];
        
        // Project to XZ plane for UV mapping
        let uvX = (x - box.min.x) / size.x;
        let uvY = (z - box.min.z) / size.z;
        
        if (displacementSettings.flipUV) {
            uvX = 1 - uvX;
            uvY = 1 - uvY;
        }
        
        uv.setXY(i, uvX, uvY);
    }

    geometry.setAttribute('uv', uv);
    return uv;
}
\end{verbatim}

This UV generation process calculates the bounding box of the mesh geometry and projects 3D vertices onto the XZ plane, creating a planar mapping.

\subsubsection{Displacement calculation and application}

Displacement implements real-time surface deformation based on image height data so mesh vertices can be moved according to the mapping previousely done based on the desired image by the user.

export function applyDisplacementMap(geometry, texture, scale, displacementSettings) {
    if (!texture || !geometry) return geometry;
    
    geometry.computeVertexNormals();

    const position = geometry.attributes.position;
    const normals = geometry.attributes.normal;
    const uv = generateUVs(geometry, displacementSettings);
    const dispMap = texture.image;

    if (!dispMap) return geometry;

    // Create canvas for image data extraction
    const canvas = document.createElement('canvas');
    canvas.width = dispMap.width;
    canvas.height = dispMap.height;
    const context = canvas.getContext('2d');
    context.drawImage(dispMap, 0, 0);
    const imageData = context.getImageData(0, 0, dispMap.width, dispMap.height);
    const data = imageData.data;

    // Process displacement per vertex
    const positionArray = position.array;
    
    for (let i = 0; i < position.count; i++) {
        // Sample displacement from image
        const ux = Math.floor(uv.getX(i) * dispMap.width);
        const uy = Math.floor(uv.getY(i) * dispMap.height);
        const pixelIndex = (uy * dispMap.width + ux) * 4;
        const displacement = (data[pixelIndex] / 255) * scale;
        
        // Apply displacement along vertex normal
        const normalX = normals.getX(i);
        const normalY = normals.getY(i);
        const normalZ = normals.getZ(i);
        
        position.setXYZ(
            i,
            positionArray[i * 3] + normalX * displacement,
            positionArray[i * 3 + 1] + normalY * displacement,
            positionArray[i * 3 + 2] + normalZ * displacement
        );
    }

    position.needsUpdate = true;
    geometry.computeVertexNormals();
    return geometry;
}
\end{verbatim}

\subsection{Usage guidelines and capabilities}

For optimal results with the drawing interface, users should draw "clear" and as "smooth" as possible profiles of their desired revolution surface. For effective displacement mapping, users should use high-contrast images where lighter areas represent raised surfaces and darker areas represent recessed areas, and add higher levels of subdividion to the meshes, as that will define the amount of vertices tha move. 

\subsection{Technical limitations and considerations}

The implementation has several limitations. The displacement mapping depends on browser Canvas API support and may be computationally intensive for very large meshes. The drawing interface works best on touch devices but also supports mouse input for desktop users even though it might not be properly responsive.

\section{\textit{AI Tools} Technical documentation}

\textit{AI Tools} plugin is an integration of artificial intelligence capabilities into parametric design workflows through Grasshopper. This technical documentation outlines the implementation of the two components that represent the plugin using external AI services to generate 3D models from text prompts and analyze images to create detailed modeling instructions.

\vspace{0.5cm}

The complete source code is available as open-source under MIT License at \href{https://github.com/jmuozan/AI_3D_Models_Grasshopper}{github.com/jmuozan/AI\_3D\_Models\_Grasshopper}, and the compiled plugin can be downloaded from \href{https://www.food4rhino.com/en/app/ai-tools}{Food4Rhino}.

\subsection{System architecture overview}

The plugin follows the Rhino Grasshopper plugin architecture and consists of two main components that integrate external AI services into traditional CAD workflows. The implementation combines Python scripts for AI service integration with C\# for Grasshopper component management.

\vspace{0.5cm}

Tech stack:
\begin{enumerate}
\item ZOO's Text-to-CAD API for natural language to 3D model generation
\item OpenAI's GPT-4 Vision API for image analysis and prompt generation
\item Python 3
\item C\# .NET Framework 4.8 
\item RhinoCommon API for geometry processing and file handling
\end{enumerate}

\vspace{0.5cm}

Plugin supports STEP, STL, and OBJ file formats, automatic file organization, and real-time integration within the Grasshopper visual programming environment, even though STEP files selected as default due to their superior compatibility with CAD software and preservation of parametric information.

\subsection{Text to CAD component implementation}

\subsubsection{Component architecture}

Text to CAD component integrates with ZOO's Text-to-CAD API to generate 3D models from natural language descriptions. The component receives four input parameters: API key for ZOO authentication, directory path for temporary file storage, text prompt describing the desired 3D model, and a boolean trigger to initiate generation. The outputs include the generated Brep geometry and the file path to the created STEP file.

\subsubsection{Python script implementation}

The core functionality is the KittyCAD API client use for integration with ZOO's machine learning services. This is how Text-to-CAD looks:

private void CompileCode(string code, string outputPath)
{
    var syntaxTree = CSharpSyntaxTree.ParseText(code);
    
    // Gather references from loaded assemblies
    var assemblies = AppDomain.CurrentDomain.GetAssemblies()
        .Where(a => !a.IsDynamic && !string.IsNullOrEmpty(a.Location) 
               && File.Exists(a.Location))
        .Select(a => a.Location)

    if (!result.Success)

private static bool TryFitCircleRobust(List<Point3d> pts, double tol,
    out Point3d center, out double radius, out bool clockwise)
{
    // Least-squares circle fitting implementation
    int n = pts.Count;
    if (n < 3) return false;
    
    double sumX = 0, sumY = 0, sumX2 = 0, sumY2 = 0, sumXY = 0;
    double sumX3 = 0, sumY3 = 0, sumX2Y = 0, sumXY2 = 0;
    
    foreach (var pt in pts)
    {
        double x = pt.X, y = pt.Y;
        sumX += x; sumY += y;
        sumX2 += x * x; sumY2 += y * y; sumXY += x * y;
        sumX3 += x * x * x; sumY3 += y * y * y;
        sumX2Y += x * x * y; sumXY2 += x * y * y;
    }
    
    // Solve for circle center using determinant method
    double a = n * sumXY - sumX * sumY;
    double b = n * sumX2 - sumX * sumX;
    double c = n * sumY2 - sumY * sumY;
    double det = a * a - b * c;
    
    if (Math.Abs(det) < 1e-12) return false;
    // Calculate center and validate geometry
}

\begin{verbatim}
public class PortParam : GH_ValueList
{
    private string _lastSelectedPort = string.Empty;
    private bool _debugMode = true;
    
    // Multi-method port detection for maximum compatibility
    private string[] GetPortsMultiMethod()
    {
        List<string> allPorts = new List<string>();
        
        // Method 1: Cross-platform SerialPortStream
        try
        {
            string[] streamPorts = SerialPortStream.GetPortNames();
            if (streamPorts.Length > 0)
            {
                allPorts.AddRange(streamPorts);
            }
        }
        catch (Exception ex)
        {
            Debug.WriteLine($"SerialPortStream error: {ex.Message}");
        }
        
        // Method 2: Standard .NET SerialPort for Windows
        if (RuntimeInformation.IsOSPlatform(OSPlatform.Windows))
        {
            try
            {
                string[] netPorts = System.IO.Ports.SerialPort.GetPortNames();
                foreach (var port in netPorts)
                {
                    if (!allPorts.Contains(port, StringComparer.OrdinalIgnoreCase))
                        allPorts.Add(port);
                }
            }
            catch (Exception ex)
            {
                Debug.WriteLine($"System.IO.Ports error: {ex.Message}");
            }
        }
        
        // Method 3: Direct filesystem access for Unix systems
        if (!RuntimeInformation.IsOSPlatform(OSPlatform.Windows))
        {
            try
            {
                string[] unixPorts = GetUnixPortNames();
                foreach (var port in unixPorts)
                {
                    if (!allPorts.Contains(port, StringComparer.OrdinalIgnoreCase))
                        allPorts.Add(port);
                }
            }
            catch (Exception ex)
            {
                Debug.WriteLine($"Unix ports error: {ex.Message}");
            }
        }
        
        return allPorts.Distinct(StringComparer.OrdinalIgnoreCase).ToArray();
    }

    // Unix-specific port detection with comprehensive device coverage
    private static string[] GetUnixPortNames()
    {
        var list = new List<string>();
        
        // macOS/FreeBSD: cu.* devices for outgoing connections
        try
        {
            if (Directory.Exists("/dev"))
            {
                var filesCu = Directory.GetFiles("/dev", "cu.*");
                list.AddRange(filesCu.Select(Path.GetFileName));
                
                var filesTty = Directory.GetFiles("/dev", "tty.*");
                list.AddRange(filesTty.Select(Path.GetFileName));
            }
        }
        catch (Exception ex) 
        { 
            Debug.WriteLine($"Error listing cu./tty.* devices: {ex.Message}");
        }
        
        // Linux: USB-to-serial adapters and Arduino devices
        try
        {
            if (Directory.Exists("/dev"))
            {
                var filesUsbTty = Directory.GetFiles("/dev", "ttyUSB*");
                list.AddRange(filesUsbTty.Select(Path.GetFileName));
                
                var filesAcmTty = Directory.GetFiles("/dev", "ttyACM*");
                list.AddRange(filesAcmTty.Select(Path.GetFileName));
            }
        }
        catch (Exception ex) 
        { 
            Debug.WriteLine($"Error listing ttyUSB/ACM devices: {ex.Message}");
        }
        
        // Ensure absolute paths for Unix devices
        for (int i = 0; i < list.Count; i++)
        {
            if (!list[i].StartsWith("/dev/"))
                list[i] = "/dev/" + list[i];
        }
        
        return list.ToArray();
    }
}

\subsection{Technical limitations and architectural considerations}

\subsubsection{Cross-platform compatibility challenges}

The implementation addresses several platform-specific challenges. For serial communication, Windows systems use \texttt{SerialPortStream} for enhanced compatibility with USB-to-serial adapters, while Unix systems implement direct FileStream access with \texttt{stty} configuration for maximum control, and automatic port detection handles different device naming conventions across platforms.

UI framework integration presents challenges where Eto.Forms provides cross-platform UI but requires careful handling of platform-specific features, hand tracking integration depends on Python MediaPipe availability and camera permissions, and QR code generation uses cross-platform libraries but display handling varies by OS.

File system access considerations include path handling that accounts for Unix vs. Windows file system differences, temporary file management that respects platform-specific conventions, and external process launching that handles different shell environments.

\subsubsection{Performance optimization strategies}

Memory management includes careful disposal of graphics resources in custom UI components, streaming-based processing for large G-code files to minimize memory footprint, and efficient mesh representation for real-time editing operations.

Asynchronous operations use HTTP client operations with proper async/await patterns and cancellation support, serial communication implements background threads with proper synchronization, and file I/O operations avoid blocking the Grasshopper UI thread.

Computational efficiency includes G-code generation using optimized algorithms for path simplification and arc detection, mesh editing maintaining spatial indices for efficient vertex selection, and preview rendering implementing view frustum culling and level-of-detail management.

\subsubsection{Security and reliability considerations}

Network communication uses HTTP server for photogrammetry with local network binding only, input validation for all external data sources including files and network requests, and proper error handling for network timeouts and connection failures.

Process management includes external Python processes with timeout handling and proper cleanup, serial communication implementing buffer overflow protection, and file operations including comprehensive exception handling.

Data validation encompasses G-code parsing with syntax validation and bounds checking, mesh geometry validation preventing invalid topology creation, and component compilation including security restrictions on generated code.

protected void POSTWithHeadersAsync(string url, string body, 
    Dictionary<string, string> headers, int timeout)
{

    {

        { 
            Timeout = TimeSpan.FromMilliseconds(timeout)

                    _currentState = RequestState.Done;
                }
                else

                _shouldExpire = true;

                client.Dispose();
            }
        });
    }
    catch (Exception ex)
    {
        _response = ex.Message;
        _currentState = RequestState.Error;
        _shouldExpire = true;
        ExpireSolution(true);
    }
